FAQ

Questions about locklog

Is locklog ready to use?

It is early and in active development: try it on non-production data first. v0.1.0 shipped files, journald, Docker and Loki, with Elasticsearch and OpenSearch as a preview.

From v0.2.0 the console is started by lox run (lockhub) only, from the lockhub release after v0.9.0. See the CHANGELOG and the install status.

Which agents does it work with?

Any MCP client: Claude Code, Codex, Cursor, Gemini CLI, …

locklog init <agent> wires one (claude, codex, cursor, gemini), and locklog doctor --fix wires the ones installed here.

Can the agent search for a clear email address?

It can try, but the console refuses it (E_PII_IN_QUERY) and points it to locklog_lookup.

Every record is masked inside the console before any predicate runs, so the agent only ever works on the masked view. Equality on a pseudonym works, so “every record of this user” still does.

Can I see a value in clear?

Yes, on the console only. Turn clear results on with Ctrl-O: the records the agent’s calls return are printed in clear on the console’s terminal, secrets kept redacted. The agent still gets the masked result, and the audit counts them as shown_clear.

An unmask screen shows its record in clear too. This is the way to read a record on production, where unmask is off.

Handing a clear value to the agent (locklog_unmask) waits for your approval at lox run, unless the profile’s auto rules say otherwise. It is off by default on production. Secrets are never unmasked or pseudonymised.

Can locklog change my logs or my backends?

No. It reads, never writes: read-only mounts, a read-only root filesystem, an allowlist of backend endpoints and no Docker socket in any locklog container.

There is no write, delete or admin operation at all.

Is pseudonymised data anonymous?

No. Pseudonymised data is still personal data under the GDPR: the model provider receives pseudonyms, timestamps and the fields locklog does not mask.

Pseudonyms link a person’s records within an epoch (7 days by default). See what is not masked.

Do I need lea?

No. On production the agent must not be able to read the logs itself: run it with lea, or in its own container (the recipe).

For a trial on non-production data, the agent can run on your own account.

Which log sources are supported?

Files (globs, rotation, gzip, zstd), journald, Docker container logs and Loki. Elasticsearch and OpenSearch as a preview; their incident gates come with v0.3.0.

Text is never sent to a backend.

What does the agent get for free?

Reads within budgets: status, sources, search, count, patterns, context, trace, tail. They are bounded per call and per hour, and audited.

A call over a budget is refused before it touches data; locklog_scan asks you once for the whole plan.

Which licence?

Apache 2.0, like the rest of the Lock Family.
