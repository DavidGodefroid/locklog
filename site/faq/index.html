FAQ

Early release. v0.1.0 is the first release of locklog (see the CHANGELOG). It is built on lockkit, and its design is public in docs/security-model.md.

Is locklog ready to use?

v0.1.0 is the first release: files, journald, Docker and Loki with the standalone console, Elasticsearch and OpenSearch as a preview. It is early and in active development: try it on non-production data first. See the CHANGELOG.

Which agents does it work with?

Any agent that speaks MCP: Claude Code, Codex, Cursor or Gemini CLI, for example. locklog setup wires the agents it detects (Claude Code, Codex, Cursor, Gemini CLI).

Can the agent search for a clear email address?

It can try, but the console refuses it (E_PII_IN_QUERY) and points it to locklog_lookup. Every record is masked inside the console before any predicate runs, so the agent only ever works on the masked view. Equality on a pseudonym works, so “every record of this user” still does.

Can I see a value in clear?

Yes, on the console only: turn clear results on with Ctrl-O, and the records the agent’s calls return are printed in clear on the console’s terminal (secrets kept redacted; the agent still gets the masked result; the audit counts them as shown_clear), and an unmask screen shows its record in clear too. This is the way to read a record on production, where unmask is off. Handing a clear value to the agent (locklog_unmask) waits for your approval at the console, is never auto-approved, and is off by default on production. Secrets are never unmasked or pseudonymised.

Can locklog change my logs or my backends?

No. It reads, never writes: read-only mounts, a read-only root filesystem, an allowlist of backend endpoints, no Docker socket in any locklog container, and no write, delete or admin operation at all.

Is pseudonymised data anonymous?

No. Pseudonymised data is still personal data under the GDPR: the model provider receives pseudonyms, timestamps and the fields locklog does not mask. Pseudonyms link a person’s records within an epoch (7 days by default). See what is not masked.

Do I need lea?

No. On production the agent must not be able to read the logs itself: run it in its own container (locklog setup --agent container); lea support is planned. For a trial on non-production data, the agent can run on your own account (locklog setup --agent host).

Which log sources are supported?

Files (globs, rotation, gzip, zstd), journald, Docker container logs and Loki; Elasticsearch and OpenSearch as a preview (their incident gates come with v0.3.0). Text is never sent to a backend.

What does the agent get for free?

Reads within budgets: status, sources, search, count, patterns, context, trace, tail, bounded per call and per hour, and audited. A call over a budget is refused before it touches data; locklog_scan asks you once for the whole plan.

Which licence?

Apache 2.0, like the rest of the Lock family.
