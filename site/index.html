Why locklog?

Logs are where personal data hides in free text: an email in an error message, a client IP in an access log, a token in a header someone logged.

An agent that runs journalctl, docker logs or grep, or queries Loki with its own credentials, sends all of it to the model provider. locklog puts a console between the agent and the logs.

Highlights

  • 🕶️

    Masked by construction

    Every record is masked inside the console before any predicate runs. A predicate holding a clear email is refused (E_PII_IN_QUERY); equality on a pseudonym still finds every record of one user.

  • 🔎

    Investigation tools, not a query language

    locklog_count, locklog_patterns, locklog_trace, locklog_context, locklog_search and locklog_tail. Text never goes to a backend.

  • ⚖️

    Free within budgets

    Reads are bounded per call and per hour. A call over a budget is refused before it touches data; locklog_scan asks you once for the whole plan.

  • 📚

    Your sources

    Files (globs, rotation, gzip, zstd), journald, Docker container logs and Loki. Elasticsearch and OpenSearch as a preview.

  • 🔒

    Read-only

    Read-only mounts and root filesystem, an allowlist of backend endpoints, no Docker socket in any locklog container, no write path to any backend.

  • 👤

    Clear values stay with you

    Handing a clear value to the agent waits for your approval at lox run, and is off by default on production. Ctrl-O shows you records in clear at the console only.

Quick start

With the lockhub release that knows locklog, on a non-production profile first:

  1. Install with Homebrew (the box above). You need a Linux host with the logs and Docker 19.03 or later.

  2. In your project, lox add locklog builds a profile from the logs this host has, wires your agent and checks the setup.

    cd your-project
lox add locklog

  3. In a terminal of its own, outside any agent, keep lox run open. It starts the console and shows every ticket.

    lox run

  4. Start your agent in the project (claude, codex, gemini, …) and ask: “when did the 502s start?”

lox add wires Claude Code. For Codex, Cursor or Gemini CLI, also run locklog init codex (or cursor, gemini).

Know the limits

locklog masks the values it detects. Person names (unless opted in), usernames in free text, postal addresses, private IPs, business ids and encoded content are not detected.

Pseudonymised data is still personal data under the GDPR. And locklog protects the logs only from an agent that cannot reach them by another path: on production, that is your container’s job, or lea’s.
