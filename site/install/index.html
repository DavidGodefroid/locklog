Install locklog

A launcher on the host, the console in its own container, and your agent placed where it cannot read the logs itself.

Pre-release, in development. No release of locklog is published yet. It is built on lockkit, and its design is public in docs/security-model.md.

Status

locklog is a pre-release, in development. install.sh installs the latest published release, so until the first one is published it has nothing to install. Follow the CHANGELOG and the releases page.

Prerequisites

  • A Linux host with the logs.
  • Docker ≥ 19.03.
  • cosign, to verify the release and the image.
  • sudo for /usr/local/bin.
  • A terminal you keep in view, where the console stays open.

Install the launcher

curl -fsSL https://locklog.dev/install.sh | sh

install.sh installs the latest published release, or LOCKLOG_VERSION=vX.Y.Z. It verifies the release with cosign before it installs a root-owned /usr/local/bin/locklog, and the launcher runs the image by its signed digest.

Read the script first

To read it before you run it, download it from locklog.dev or from the repository:

curl -fsSLO https://locklog.dev/install.sh   # or raw.githubusercontent.com/DavidGodefroid/locklog/main/scripts/install.sh
less install.sh && sh install.sh

locklog update moves to another release; locklog version shows the launcher’s and the image’s versions.

Trial, on a non-production profile

About five minutes. Run it on a non-production profile: your agent runs on your own account, where it could still read the logs directly.

# Describe your logs: setup detects files, journald and containers,
# asks whether the profile is production (answer "no" for the trial),
# and wires the detected agents (Claude Code, Codex, Gemini CLI)
locklog setup --agent host

# The console, in a terminal you keep in view (setup prints the line;
# containers get a profile of their own, <profile>-docker)
locklog console --profile <profile>

Then, in another terminal, ask your agent: “when did the 502s start?”. It calls locklog_count, locklog_patterns and locklog_trace; the console shows each call and asks you only when the agent wants more than the free budgets or a value in clear. In this trial the MCP server runs as the image’s agent account, launched from your account, and the launcher’s mcp refuses production profiles.

For production

On production the agent must not be able to read the logs, the Docker socket or the backends itself (precondition P1). Run it:

  • In lea

    Planned: no lea release supports locklog yet (locklog setup --agent lea says so). Use your own container meanwhile.

  • In its own container

    locklog setup --agent container prints a tested Dockerfile snippet for your agent image and the docker run line. The agent user must not have sudo.

Your agent CLI’s own login (Anthropic, OpenAI, Google) is yours to set up. Then run locklog doctor where the agent runs: it checks the common ways P1 fails, and on a production profile its findings are errors.
